# مصادقة حسابات الإدارة

تستخدم لوحة الإدارة جلسة ASP.NET Core Identity عبر Cookie آمنة لأن الواجهة والـAPI مستضافان على نفس الدومين. لا تُحفظ كلمات المرور أو رموز الجلسة في `localStorage`.

## المسارات

| Method | Route | الاستخدام |
|---|---|---|
| GET | `/api/v1/admin/auth/csrf` | إصدار رمز CSRF للمتصفح |
| POST | `/api/v1/admin/auth/login` | تسجيل الدخول بالبريد وكلمة المرور |
| GET | `/api/v1/admin/auth/me` | التحقق من الجلسة الحالية |
| POST | `/api/v1/admin/auth/logout` | إنهاء الجلسة الحالية |

قبل `login` أو `logout`، يطلب المتصفح الرمز من `csrf` ويرسل قيمة `token` في ترويسة `X-CSRF-TOKEN`. يجب إرسال الطلبات مع بيانات اعتماد المتصفح (`credentials: "include"`). يتطلب تسجيل الدخول HTTPS. الجلسة HttpOnly، وSameSite=Lax، ومدتها 8 ساعات مع تجديد أثناء النشاط.

رد تسجيل الدخول الفاشل موحد ولا يكشف هل البريد مسجل. بعد خمس محاولات فاشلة، يُقفل الحساب لمدة 15 دقيقة. تتطلب كلمة المرور 8 أحرف على الأقل وتضم حرفًا كبيرًا وصغيرًا ورقمًا ورمزًا.

مثال مبسط للتدفق من الواجهة:

```ts
const csrfResponse = await fetch("/api/v1/admin/auth/csrf", {
  credentials: "include",
});
const { token } = await csrfResponse.json();

await fetch("/api/v1/admin/auth/login", {
  method: "POST",
  credentials: "include",
  headers: {
    "Content-Type": "application/json",
    "X-CSRF-TOKEN": token,
  },
  body: JSON.stringify({ email, password }),
});
```

لإنشاء أول حساب محلي، استخدم أداة الإعداد الموضحة في [إعداد قاعدة البيانات محليًا](../Database/LocalSetup.md). لا يوجد مسار عام لإنشاء حساب إدارة.


## الخروج وانتهاء الجلسة

تحتوي صفحات الإدارة على زر خروج يرسل طلب `POST /api/v1/admin/auth/logout` مع رمز CSRF وبيانات اعتماد المتصفح. بعد نجاح الطلب تُمسح بيانات الإدارة المؤقتة ويعود المستخدم إلى صفحة الدخول. إذا كانت الجلسة منتهية أصلًا، يعامل العميل استجابة `401` من مسار الخروج كجلسة منتهية ويعيد المستخدم للدخول.

تتحقق الواجهة من الجلسة عند التركيز على الصفحة، وكل 60 ثانية أثناء بقائها مفتوحة. إذا انتهت الجلسة، يحوّل المسار المحمي المستخدم إلى `/login`. كما ترفض الـAPI أي طلب إداري بعد الخروج أو انتهاء Cookie الجلسة.

**دليل تحقق يدوي:** سجّل الدخول، افتح صفحة إدارية، ثم استخدم زر الخروج وتأكد من ظهور صفحة الدخول. سجّل الدخول مجددًا، احذف Cookie `WedLink.Admin` من أدوات المتصفح أو سجّل الخروج من نافذة أخرى، وانتظر حتى 60 ثانية أو أعد التركيز على الصفحة؛ يجب أن تعود الواجهة إلى صفحة الدخول. جرّب بعدها فتح مسار إداري مباشرة وتأكد من عدم عرضه.

## إدارة حسابات الإدارة

إدارة الحسابات والأدوار محصورة في SuperAdmin. الحسابات التي تحمل دور Admin لا تستطيع تسجيل الدخول إلى لوحة الإدارة أو الوصول إلى مساراتها. الأدوار التي يديرها النظام هي `Admin` و`SuperAdmin`.

| Method | Route | الاستخدام |
|---|---|---|
| GET | `/api/v1/admin/users` | عرض حسابات الإدارة وحالتها وأدوارها |
| POST | `/api/v1/admin/users` | إنشاء حساب وتعيين دور أو أكثر |
| PATCH | `/api/v1/admin/users/{userId}/status` | تفعيل الحساب أو إيقافه |
| PUT | `/api/v1/admin/users/{userId}/roles` | تغيير أدوار الحساب |

كل طلب تغيير يتطلب CSRF. لا يمكن للمستخدم إيقاف حسابه أو إزالة دور SuperAdmin عن نفسه، ولا يمكن إيقاف أو تخفيض آخر SuperAdmin نشط. تغيير حالة الحساب أو أدواره يغيّر Security Stamp، وتُراجع الجلسة عند كل طلب حتى تُلغى الجلسات المفتوحة فورًا.

**دليل تحقق يدوي:** سجّل الدخول بحساب SuperAdmin، افتح `/admin/users`، وأنشئ حساب Admin. تحقق أن الحساب ظاهر وأن تسجيل دخوله لا يفتح لوحة الإدارة. أوقف الحساب ثم تحقق أن جلسة SuperAdmin ثانية مفتوحة لذلك الحساب تُرفض في الطلب التالي. جرّب تغيير الأدوار أو إيقاف حساب SuperAdmin الحالي وتأكد أن الخادم يرفض ذلك.
